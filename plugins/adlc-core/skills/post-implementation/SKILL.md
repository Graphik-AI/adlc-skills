# Post implementation

Close out the authorized task with an evidence-backed account. Read the current request, applicable instructions, existing handoff/tracker, acceptance requirements and complete relevant Git state, including staged, unstaged and in-scope untracked files. Preserve unrelated work.

Finish outstanding in-scope work and fixes introduced by the change. Inspect the final diff and reuse valid checks; rerun those invalidated by changes or findings. Update existing affected documentation and substantial-work continuity with objective, decisions, current checkout, results, limits and a next action only if work remains.

Use the actual tracker, including [local Markdown](../../references/issue-tracker-local.md) where appropriate. Never invent a GitHub issue. External comments or closure need authority for that action/target; automatic selection of this skill does not grant it. Preserve explicit manual-review pauses, but do not add a new universal gate before already-authorized commits or other scoped work.

Stage only in-scope files and commit when authorized. Close tickets only when their criteria and project rules are satisfied. Report code completion, local checks, runtime evidence, developer acceptance and delivery separately. Do not describe an agent review as human acceptance.

Give a concise account of what changed, why, verified outcomes and material gaps. Provide manual steps only where they establish missing or requested evidence, with exact safe targets and expected results. Stop at the task boundary. A next-ticket prompt, external comment, deployment, operational handoff or ongoing operations is not a mandatory closeout step.
